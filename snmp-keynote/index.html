What is SNMP?

An IETF standard for monitoring and managing network devices from one central place.

Monitor

Read health and performance: CPU, memory, traffic, uptime.

Manage

Change supported settings on a device, remotely.

Alert

Hear about problems the moment they happen, often before users notice.

Where SNMP lives

A small application-layer protocol riding on fast, connectionless UDP.

MIB & OID: addressing the data

The MIB is a tree of all the data. An OID is the path to one value.

1.3.6.1.2.1.1.3 = sysUpTime, how long the device has been running. The final .0 means its single instance.

Hands-on with Net-SNMP

The same operations, typed by a network admin.

admin@nms: ~
# lab network · 10.0.0.20 is srv-db, a Linux server running the Net-SNMP agent
$ snmpget -v2c -c public 10.0.0.20 sysName.0
SNMPv2-MIB::sysName.0 = STRING: srv-db
$ snmpwalk -v2c -c public 10.0.0.20 system
SNMPv2-MIB::sysDescr.0 = STRING: Linux srv-db 6.8.0 x86_64
SNMPv2-MIB::sysObjectID.0 = OID: NET-SNMP-MIB::netSnmpAgentOIDs.10
DISMAN-EVENT-MIB::sysUpTimeInstance = Timeticks: (364051200) 42 days, 3:15:12.00
SNMPv2-MIB::sysContact.0 = STRING: lab admin
SNMPv2-MIB::sysName.0 = STRING: srv-db
SNMPv2-MIB::sysLocation.0 = STRING: server room, rack 2
$ snmpget -v3 -l authPriv -u admin -a SHA -A ******** -x AES -X ******** 10.0.0.20 sysName.0
# same answer, now authenticated and encrypted
SNMPv2-MIB::sysName.0 = STRING: srv-db

Strengths and limits

Why SNMP is everywhere, and what to watch out for.

Strengths

  • LightweightSmall messages over UDP
  • UniversalAlmost every router, switch, server and printer has an agent
  • Open standardDefined by the IETF, not tied to one vendor
  • Instant alertsTraps report problems the moment they happen
Click a block

Limits

  • Messages can be lostUDP has no delivery guarantee: use INFORM for key alerts
  • Weak old securityv1 and v2c send the community in plain text
  • Polling trafficAsking thousands of devices often adds load
  • Limited configurationModern networks add NETCONF and YANG

Best practices

Use SNMPv3 with authPriv

Authentication and encryption on every message

Change "public" and "private"

Attackers try the default community strings first

Restrict access with ACLs

Only the manager's address may talk to agents

Watch traps continuously

An alert nobody reads protects nobody

Quick quiz

Answer out loud first, then tap an option to check.

01

Which UDP port receives traps?

Traps go to the manager on 162. Requests go to agents on 161.

02

Which version adds authentication and encryption?

Only SNMPv3 has user-based security (USM).

03

Which operation changes a value on a device?

GET reads, SET writes, TRAP alerts.

04

How is an INFORM different from a TRAP?

The manager sends a Response back to every INFORM.
